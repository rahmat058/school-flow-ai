## Decisions

- Backend is NestJS + PostgreSQL via Supabase — all API calls target `/api/v1`
- Recharts (not Chart.js) for charts — already installed
- State: Zustand for client-only global state (auth/session, school context) — no Redux
- Server state: TanStack Query 5 for all `/api/v1` data — query/mutation hooks in feature `api.ts` with cache + invalidation; never cache API responses in Zustand
- Animations: `motion` v13 for UI transitions — React APIs imported from `motion/react`; `framer-motion` is the legacy package name for the same library and must not be imported directly
- Dates: date-fns for formatting and academic-calendar helpers
- Reports: @react-pdf/renderer for PDF export (report cards, invoices)
- Mock data in `src/data/` is temporary; replace with API calls per phase
- Design tokens follow `docs/frontend/Design.md` — indigo primary, 4px grid
- UI primitives are hand-rolled from raw HTML + Tailwind in `src/components/ui/` — no component library (no Radix/Headless UI/shadcn). `motion` (`motion/react`) provides all animation, and `MotionConfig reducedMotion="user"` in `main.tsx` makes it respect OS reduced-motion settings.
- Toast motion follows **react-toastify**: a **Bounce** entrance/exit, a countdown progress bar, hover-pause, and swipe-to-dismiss. Auto-dismiss is a `motion` value animation (`animate(progress, 0, …)`), not a `setTimeout`, so the bar and the timer pause/resume together.
- Class names render as **`1-A`** (grade-section) via `classLabel` / `classLabelFor` in `data/classes.ts` — bare, with no `Class` prefix (each call site adds its own where it reads). Subject codes are the **catalogue's own** (`MATH`, `ART`) and are no longer suffixed with the class — the class comes from the row's `class_id`, and the code is school-wide.
- **Fees module:** one `/fees` route with five `Tabs`; a student's collect view is a **route** (`/fees/collect/:studentId`) while every form is a `Sheet` and only the receipt preview is a `Modal`. Invoices are billed **per fee head**, so a row's title is the head's own name. Currency stays **USD** (`formatPaise`) — the reference screenshots' `₹` was not adopted.
- **Receipts print through a throwaway iframe** (`features/fees/lib/receipt.ts`) rather than global print CSS, so only the receipt reaches the printer and no dependency is added.
- `PaymentMethod` carries **`DEMAND_DRAFT` and `ONLINE`** (contract + `Database.md` §2), because the counter-collect form offers Cash / Online / Cheque / DD; `Concession` carries a **`category`** (`SIBLING`/`MERIT`/`SC_ST`/`CUSTOM`/`STAFF_WARD`) distinct from its percentage-vs-flat `type`.
- Auth session lives in a **Zustand** store (`src/store/auth.ts`) — access token in memory only, restored on reload via `POST /auth/refresh`. `Architecture.md`'s old `context/` entry was replaced by `store/`.
- Demo data is served **through** axios via a custom adapter, not around it: hooks, interceptors, JWT attach and error envelopes are exercised exactly as they will be against the backend. `VITE_ENABLE_MOCKS=false` switches to the real API with no other change.
- Route structure: `src/routes/paths.ts` is the single source of route strings; `publicRoutes.tsx` / `privateRoutes.tsx` are plain `RouteObject[]` composed by `AppRoutes`; pages are `React.lazy` so each ships as its own chunk.
- Guard _decisions_ are pure functions in `routes/guards/guardDecision.ts` (testable without a DOM — React Router's `<Navigate>` is a no-op on a static render, and zustand v5 serves its initial state to server renders).
- Demo logins: `admin@` / teacher / student / parent accounts at `brightfuture.edu`, password `demo1234`; the signup OTP is `123456`. Both are shown on the login screen while mocks are on.
- Forms use **react-hook-form** for state and validation. The `components/ui` input primitives must accept a ref (`ComponentPropsWithRef`) so `register()` works; select/checkbox/radio/switch are non-native and need `Controller` when a form uses them (no form does yet).
- **Debt:** no DOM test runner is installed, so interaction (submit, redirect, pagination clicks, the sidebar toggle itself) is unverified by automation, and **portalling components cannot be render-verified at all** — `react-dom/server` rejects portals outright ("Portals are not currently supported by the server renderer"), so `Modal`, `Sheet` and `ConfirmDialog` sit outside the Node smoke checks by construction. Verification to date: `tsc -b`, eslint, prettier, `vite build`, plus Node smoke tests over the axios/mock layer (11 cases), the guard decisions, the auth-page rendering (13 cases), react-hook-form field binding (10 cases), the currency/brand/rail classes (6 cases), the login UX (6 cases), the dashboard (8 cases incl. the write-free board) and the students roster (8 cases) and its write flow (7 cases).
- **Homework module:** `/homework` is readable by every role — the write controls are the page's own (`ADMIN`/`TEACHER`) rather than a `RoleGuard` on the route, and `GET /homework` is role-scoped in the API (staff / own class / children's classes). The assignment form is a `Sheet` whose Subject list loads per class, `maxMarks` is nullable (`null` = unmarked), and `DELETE` is a soft delete via `deletedAt` — the status pill on a card is derived from `dueDate`, never stored.
- **Timetable module:** reads are open to every role (the grid renders read-only, with no hover lift and no cell buttons), writes are `ADMIN`-only per the API contract. Period rows are **managed class-wide** through class-scoped routes (`…/slots`, `…/periods`) while the schema keeps them stored per day. Subject tones are a stable **sorted-order** map over the palette's existing soft fills — no new colours — and the TIME column's soft gradient wash is the single documented gradient exception in `Design.md`. Deleting a row is confirmed through the page's `ConfirmDialog`, which stacks above the open sheet.
- **Study materials module:** one `/study-materials` route (the API keeps `/materials`) holding a card-grid library. Reads are open to every role with the list **role-scoped server-side** (staff / own class / children's classes) while the page withholds upload and delete from students and parents; upload is the app's only **multipart** write (`apiClient.postForm()` plus a `FormData`-aware mock adapter), and the file rule (PDF/JPG/PNG/DOCX ≤ 10MB, `lib/validation.ts`) is enforced by both the picker and the API; `DELETE` is a soft delete. The kind comes from the **URL's extension**, never the material's `type` — `type` is the school's own label (notes, worksheet, …) and says nothing about the file format. The modal owns its `GET /materials/:id` read (`useMaterialDetail`, enabled only while a row is picked) and carries its own Download in the footer; the imperative download path was renamed `fetchMaterialDownload` → `fetchMaterialDetail` because it now serves both actions. **Demo caveat:** a seeded row's `fileUrl` is a Cloudinary-shaped placeholder, so previewing one frames a dead link — exactly what clicking Download already did; a real asset previews.

So a material's **type / subject / class** tags are solid fills with white text — `bg-primary`, `bg-secondary` (the palette's green, previously unused) and `bg-ink-muted` — and `Design.md` has a **Classifying tags** bullet saying so. The two vocabularies stay apart: `StatusBadge`/`AttendanceBadge` remain semantic, and a tag never borrows a status tone.
- **A share bar is always left-anchored, with its value after it.** `Progress` has always filled from the left — its fill is a left-anchored child of the track — but placing the whole group in a **right-aligned** cell with `ml-auto` anchors the _track_ to the right edge, so at 31% the coloured part sits far right with the empty grey stretching left and the bar reads as filling backwards (reported on the My Results percentage column). The fix is the roster's arrangement: `w-16 shrink-0` track plus the percentage after it, in a default-aligned cell. `Design.md`'s Tables bullet now states the rule, and the Percentage header dropped its `align="right"`.

The report tiles are a local `ReportStat` (icon chip + value + label, **no delta**) rather than the dashboard's `StatCard`, and a report's figures stay ink — the icon chip alone carries the tone. The Attendance filters are **staged** behind `Generate` (the reference's behaviour), not applied per keystroke. `Exam Results` reports **one paper** (an exam's subject for a class), not a whole exam, because the screen shows a single Marks column; a student with no mark is `ABSENT` (a new neutral `StatusBadge` state) and is excluded from the average. Exports are client-side via the shared `lib/csv.ts` (moved out of `features/fees/lib/`), so `/reports/export` stays a server option for large datasets. The demo's 24-students-across-20-classes roster makes a per-class report 1–2 rows — a known data gap, not a bug.

The **teacher lives on the assignment**, not the subject, because the same subject is taught by different staff in each class; `classSubjectFor(classId, subjectId)` is how every module resolves it. A `subjectId` is therefore only meaningful **with** a `classId`, and each mock route validates the pair. Deleting a subject cascades its assignments and is refused (409 `SUBJECT_IN_USE`) while a lesson, paper, **mark**, homework or material still points at it — `name` and `code` are each unique per school, compared case-insensitively.

Either rename to cents and update the backend contract, or keep paise as the storage unit and treat USD as display-only — needs a decision.

The **School Profile** tab writes the school's **columns** (`PATCH /schools/current`); Academic, Notifications and Security each write **only their own slice** of the one `schools.settings` JSONB, so the three saves can never clobber one another. The build follows `Design.md` over the reference screenshots: indigo primary (not the screenshots' orange), a neutral section icon chip, and toggles set to the right of their labels.

The student payload comes from `GET /dashboard/student`, which takes the student from the **session**: no id in the path, 403 `DASHBOARD_FORBIDDEN` for a non-student account. Every figure is the read model the child's own screens already show — the register totals, the invoices, the published marks — so a guardian and their child cannot be shown different numbers. Two rules: the progress chart plots **exactly the rows the results list shows**, and **pending homework is derived** from the absence of a submission, never a stored status.
- **The attendance month is one view for three roles.** `/attendance` branches by role — staff get `ClassAttendancePanel`, a student `MyAttendancePanel`, a guardian `ParentAttendancePanel` — and all three render the same `AttendanceMonthView`, because a student's month and a class's are the **same register rows rolled up**: `GET /attendance/monthly` and `GET /attendance/me` return one shape, and only a personal month carries a per-day `status` (a class day carries its counts). `/attendance/me` is **self-scoped** like `/timetables/me`: the student comes from the session, a guardian may pass one of their own children via `?studentId=`, and a staff account or another family's child is a 403. The picker lists the payload's `availableMonths` rather than calendar months, so an empty month is never offered, and `keepPreviousData` holds the current month while the next loads. **Absent includes leave** everywhere (the roster's rule), so `present + absent + late = total`; the `leave` count and the day's true status are still shown. Attendance's status pill is `AttendanceBadge` in `components/ui/Badge.tsx`, not `StatusBadge` — its `ABSENT` wants the error tint, where `StatusBadge`'s `ABSENT` means "no mark" in the reports and stays neutral. That page was the last placeholder, so `PlaceholderPage` and the `upcomingModules` mechanism are gone. The view also draws the **month calendar**, but only for a **personal** month — a class day carries counts rather than a status, so there is nothing to dot — and its dot tones come from the same module-level `attendanceDotTone` map the day rows use, so a colour cannot mean two things. The four tiles are Present / Absent / Late / the rate, and a guardian's child is named by a header chip rather than a name line.
- **The register is written a whole day at a time.** `GET /attendance?classId=&date=` derives its roster from the **class** (not the register's rows), so an unmarked day still opens complete and a write can upsert every student in one batch; the marking sheet defaults an unmarked student to `PRESENT` — a register is marked by exception — and is keyed on the class, with the draft dropped when the date changes, because a new day is a new register. The shared `AttendanceMonthView` takes the write action as an optional **`action`** slot, so only the staff panel can render one; the student/guardian panel has no endpoint to back it.
- **A route that serves several roles reads one self-scoped endpoint, and the dashboard components are split the same way.** `ExamsPage`, `DashboardPage` and `AttendancePage` choose their view from `useCurrentUser().role` instead of a `RoleGuard`, so one URL serves every half. The record read (`GET /exams/me`) takes a student from the **session** and a guardian's child from `?studentId=` — no id in the path, `403 EXAM_FORBIDDEN` for staff and `403 PARENT_FORBIDDEN` for another family's child — and returns **published marks only**, plus display-ready counts, so a screen never rolls up its own list; a guardian's Results view and a student's Tests & exams view therefore render the very same payload. `features/dashboard/` mirrors that split: an `admin/`, `student/` and `parent/` folder with the genuinely shared pieces in `common/`, imported **by path** — there is deliberately no barrel, matching how every other feature imports its components. A student's Tests tab reads only their own class, so the demo data gives **every** class tests rather than four hand-picked ones.
- **The sidebar is curated per role, and a collapsed rail labels its icons on hover.** `navItems` carries `/exams` **twice** — "Tests & exams" for staff and students, **"Results"** for a guardian — and a guardian sees only five items (Dashboard, Attendance, Results, Fees, Notices). Homework, Timetable, Study materials and Communication are staff-and-student in the sidebar, though their routes stay reachable and their APIs still role-scope a guardian; the nav's doc comment records that the **sidebar** is what is curated, not the capability. Collapsing the rail hides the labels with `max-width`/`opacity` rather than unmounting them, and every heading it hides — the **school** at the top, each **nav item**, the **account** and **sign out** at the foot — is wrapped in a `Tooltip` with `disabled={!collapsed}`, so icon-only mode still says what each mark is. **The bubble is portalled** (`createPortal` into `document.body`, `position: fixed`, placed from the trigger's rect): an in-subtree absolute bubble is cropped by any scrolling ancestor, and the nav scrolls — which is why only the school's label used to show. Icon-only mode also **stacks** the account and the logout, because side by side they overflow the 76px rail, and the hidden name block collapses on both axes so it takes no height in the column.
- **The header states the school, not the person.** A neutral chip (building mark + name) sits where the caller's full name used to be, and the account avatar beside it keeps the name in its menu and its accessible label. It is a **label, not a switcher** — there is one school to be in, because the tenant comes from the session. That change made the header's `title` prop dead (every page renders its own `<h1>`), so it was removed along with `AppShell`'s `findNavItem`/`useLocation` resolver — the sidebar already distinguishes "Results" from "Tests & exams", which was all the role-aware title was for.
- **A chip shows its meaning, so nothing in the Tests & exams module is left grey.** The exam type is a **_category_, not a state** — one shared `ExamTypeBadge` carries the informational primary tint in all three places that render it, rather than per-type colours that would make a `FINAL` look like an error. The countdown is a **_ramp_** — error today or overdue, warning within three days, primary beyond — and the student's per-tab count badges take the tone of what they count (Tests warning, Exams primary, My Results success). Only two things stay deliberately neutral: a subject with **no marks entered yet** (there is no state to colour) and the schedule chips inside an expanded exam row, which are a detail panel rather than status. A share (a result's percentage) always draws as the roster's slim tinted bar with its percentage beside it.
- **Every component lives under a role folder, with `admin/` as the default bucket.** `features/dashboard/` holds its `admin/`, `student/` and `parent/` halves around a `common/` of the pieces all three read (`StatCard`, `StatGrid`, `UpcomingExamsCard`, `iconTone`); the shell stays in `components/layout/` and the design-system primitives in `components/ui/`. Every feature owns `features/<name>/components/<role>/`: `exams` splits `admin/` vs `student/`, and `attendance` has `admin/`, `student/` and `parent/` around a `common/` holding the view they share, while the other 13 authenticated features keep their components in `admin/` until another role needs one — then that component moves to its role folder, and anything shared goes to `common/`. `features/auth/` is the one exception: its screens are public and roleless, so its components stay flat in `features/auth/components/`. `admin/` is a bucket, not an access claim — the API still gates data by role. Every component is imported by **explicit path**; there is no barrel.
- **A fee account is read and paid through the same self-scoped `/fees/me` pair, for a student and a guardian alike**, matching `/exams/me`, `/attendance/me`, `/timetables/me` and `/dashboard/student`: the student comes from the session, a guardian may name only one of **their own** children (`?studentId=`), and anyone else's child — or invoice — is a 403. The overview carries the **records** (every invoice, billed **net of concession** so `paid + balance = total` holds on each row), the **months** grouping and display-ready **counts**, so the four tiles and the progress bar never roll up a list; the records filter narrows only what is already loaded. `PayFeeModal` lives in `features/fees/components/common/` because both roles render it — its API call resolves the caller's own student, so the form is role-agnostic. It stays the **one `Modal`** in the record flows; everywhere else a create/edit opens in a `Sheet` and only a receipt preview is a Modal.
- **The AI assistant is role-conditional, and `/ai/chat` is one feature with a role-scoped template.** The rail is `aiToolsForRole(role)` — student: AI Tutor, Quiz Generator, Homework Helper; admin: AI Tutor, Quiz Generator, Event Planner, Notice Generator; teacher: Quiz; guardian: none (`PRD.md` §4.12). A tool declares its form as **field descriptors** (`optionsFrom` pulls a select's options from the API, `prefill` copies attributes off the chosen record) and its `panel` (`chat` or `form`), so one panel pair renders all five; components live in `features/ai/components/common/` because the screen serves two roles. The assistant's forms read **only the caller's own context** — `GET /ai/context` for the class chip and subject list, `GET /homework` for the picker — never the staff-only `/classes` or `/subjects` reads. AI output is **rendered as markdown by a small in-repo renderer** (`AiMarkdown`: React nodes, no dependency, nothing injected), not a monospace block. Chat sending and form generating stay inert until the `AiModule` lands.
- **A count bubble is one component, hard-filled.** `CountBadge` (`components/ui/Badge.tsx`) renders every count in the app — the header bell's unread badge and the record size beside a tab label — as a solid fill with white text (`min-w-4`, 10px, tabular, `className` for placement). The `-soft` tints are unreadable at that size, so a count never uses one. The tone carries meaning only where there is any (the bell ramps primary → warning → error with the backlog) and is otherwise a calm accent. Any future count should render this component rather than a local pill — the two hand-rolled `TabCount` helpers it replaced had already drifted from the bell.
- **The header bell counts unread chat messages** — there is no notification model and no unread concept on notices, so `ConversationListItem.unreadCount` is the only source. Its badge is tinted by backlog size (primary → warning → error), which is as "colorful" as the palette allows; it refreshes on mount/navigation, and realtime is a follow-up.
- **Progress is a student's own self-scoped read** (`GET /progress/me`), matching `/dashboard/student`, `/exams/me`, `/attendance/me` and `/timetables/me`: the student comes from the session, there is no id in the path, and any other role is a 403. It projects **published** marks only (`report_cards` for the rank, `results`/`exam_subjects` for the trend and the per-subject means, `results.remarks` for the teacher remarks), a **missed paper is excluded from every average** — absence is a state, not a score, the reports' own rule — the class mean weights each classmate equally, and GPA is the average percentage on a 10-point scale. The route and the sidebar item are **STUDENT-only**; there is deliberately no staff equivalent of this screen.
